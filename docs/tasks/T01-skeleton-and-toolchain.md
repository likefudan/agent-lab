# T01 Project skeleton and isolated toolchain

- Depends on: T00
- Design sections: 6.1, 6.2, 8.1, 8.2
- Size: medium

## Goal

Set up a Python project skeleton that works after a clone plus one script, and leaves nothing behind outside the project directory. Every later task builds on it.

## Scope

In scope:

1. `bootstrap.sh`:
   - downloads pinned uv and cloudflared into `.tools/bin/`, with versions and sha256 from `config/tools.toml`; exits immediately on a checksum mismatch;
   - uses uv to install the Python version in `.python-version` into `.tools/python` (`UV_PYTHON_INSTALL_DIR`);
   - runs `uv sync --frozen` to install dependencies into the project's `.venv`;
   - is idempotent: skips anything already installed at the right version.
2. `.tools/env.sh` (generated by bootstrap): exports `AGENT_LAB_HOME`, `UV_CACHE_DIR`, `UV_PYTHON_INSTALL_DIR`, `HF_HOME`, `XDG_CACHE_HOME` and `HF_HUB_DISABLE_TELEMETRY=1`, and adds `.tools/bin` and `.venv/bin` to `PATH`.
3. An `./alab` wrapper script at the repository root that loads `env.sh` and runs the CLI, so users never edit their shell configuration.
4. `pyproject.toml`, `uv.lock`, `.python-version`; Python package `src/agent_lab/`.
5. `agent_lab.paths`: every path (`var/models`, `var/logs`, `var/run`, `var/bench`, `var/secrets`, `.tools`) derives from `AGENT_LAB_HOME`; no other module builds paths on its own. `var/secrets` is created with mode 700.
6. `agent_lab.config`: reads `config/profiles/*.toml`, validates fields, and gives clear error messages. Start with `mac-24gb.toml`, using the fields in design section 6.4.
7. An `alab` CLI skeleton (Typer or argparse; pick one and explain why in the PR). This task only implements `alab version` and basic `alab doctor` checks: Apple Silicon or not, physical memory, macOS version, free disk space where `AGENT_LAB_HOME` lives, and toolchain integrity.
8. Update `.gitignore`: add `.tools/` and `var/`; remove the Open WebUI and vector-database entries left over from the old design.
9. Update `README.md`: one-line description, quick start (three commands), link to the design.
10. GitHub Actions on a macOS arm64 runner: lint (ruff), type checking (optional), unit tests and the isolation check.

Out of scope: model downloads, starting the inference server, the GPU limit, the gateway, running cloudflared (this task only downloads and verifies it).

## Acceptance criteria

- [ ] On a fresh clone, `./bootstrap.sh && ./alab doctor` succeeds and prints chip, memory, macOS version and free disk space.
- [ ] Isolation check: in CI, point `HOME` at a new empty temporary directory, run bootstrap and doctor, and confirm the directory is still empty afterwards; `git status --porcelain --ignored` shows every new file under `.tools/`, `.venv/` or `var/`.
- [ ] Running `./bootstrap.sh` again downloads nothing and is clearly faster.
- [ ] Tampering with the uv or cloudflared sha256 in `config/tools.toml` makes bootstrap fail with a clear error.
- [ ] Deleting `.tools/`, `.venv/` and `var/` returns the repository to its freshly cloned state.
- [ ] Device test: run bootstrap and doctor once on the MacBook Air M5 and paste the output.
- [ ] CI passes.

## Notes

- Choose the uv and Python versions in the PR (current latest stable) and pin them.
- Never rely on any Python already on the machine; even if Homebrew Python is installed, it must not be used (doctor prints the interpreter path so this can be checked).
